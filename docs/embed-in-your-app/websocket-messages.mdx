# Websocket Messages

Websocket messages are used to exchange data between the client and the server when a collect is in progress.

You can get the ws url with the endpoints:
- [`POST /user`](/docs/api#tag/User/paths/~1user/post)
- [`POST /user/{userId}/credential/{credentialId}/collect`](/docs/api#tag/Credential/paths/~1user~1{userId}~1credential~1{credentialId}~12fa/post)

Messages sent from the Server to the Client are called Requests.
Messages sent from the Client to the Server are called Responses.

## State Message

**State Request** is sent on connection and everytime the collection state changes. 
It is used to update the progress bar and be notified when the collect is finished.

```typescript
{
    "type": "state",        // Always "state"
    "state": {
        "index": 1,         // Number between -2 and 7
        "max": 7,           // Maximum number of steps in the collect process
        "title": "...",     // Title of the state
        "message": "..."    // Message of the state
    }
}
```

No **State Response** is expected from the client.

## Twofa Message

**Twofa Request** is sent when the user needs to perform a 2FA challenge.

```typescript
{
    type: "twofa",        // Always "twofa"
    instructions: "...",  // Instructions for the 2FA challenge
    push: false,          // Whether this challenge is a push notification and requires no input code
    authLink: false,      // Whether this challenge requires an authentication link
}
```

**Twofa Response** must be sent along with the code/authLink requested by the server.
Leave the fields empty if the challenge is push.

```typescript
{
    type: "twofa";  // Always "twofa"
    twofa: "...";   // The 2FA code or authentication link provided by the user
}
```

## Oauth2 Message

**Oauth2 Request** is sent when the user needs to authenticate using OAuth2.
It contains the URL where the user should be redirected to complete the authentication:

```typescript
{
    type: "oauth2",   // Always "oauth2"
    url: "...",       // The OAuth2 authentication URL
    iframe: false,    // Indicates if the OAuth2 URL can be opened in an iframe
}
```

No **Oauth2 Response** is expected from the client.

## Interactive Message

**Interactive Request** is sent to request the user to login using video stream, we call it "interactive login".

```typescript
{
    type: "interactive";    // Always "interactive"
    reason: "open";         // Always "open"
    instructions: "...";    // Instructions for the user
}
```

**Interactive Response** is sent to end the interactive login process
- `close`: User has completed the interactive login process as expected
- `cancel`: User cancelled the interactive login
- `remove`: User cancelled the interactive login and the credential must be removed
- `report`: User reported an issue with this collector

```typescript
{
    type: "interactive";                                // Always "interactive
    reason: "close" | "cancel" | "remove" | "report";   // Reason why interative login is finished
}
```

## Screenshot Message

**Screenshot Request** is sent during the interactive login.
It contains a screenshot of the browser everytime the UI changes:

```typescript
{
    type: "screenshot",  // Always "screenshot"
    screenshot: "...",   // Base64 encoded image
    width: 1920,         // Screenshot width in pixels
    height: 1080,        // Screenshot height in pixels
}
```

No **Screenshot Response** is expected from the client.

## Resize Message

No **Resize Request** is expected from the server.

**Resize Response** can be sent during interactive login.
It requests the server to resize the browser to the specified dimensions:

```typescript
{
    type: "resize";             // Always "resize
    width: 1920;                // New width of the client window in pixels
    height: 1080;               // New height of the client window in pixels
    deviceScaleFactor?: 1.2;    // Optional device scale factor (e.g., for high-DPI displays)
}
```

## Click Message

No **Click Request** is expected from the server.

**Click Response** can be sent during interactive login.
It simulate a click on the screenshot:

```typescript
{
    type: "click";  // Always "click"
    x: 0.4522;      // X coordinate in relative (0-1) or absolute pixels of screenshot width
    y: 0.8657;      // Y coordinate in relative (0-1) or absolute pixels of screenshot height
}
```

## Keydown Message

No **Keydown Request** is expected from the server.

**Keydown Response** can be sent during interactive login.
It simulates a keydown event:

```typescript
{
    type: "keydown";    // Always "keydown"
    key: "...";         // Key name (e.g., 'Enter', 'Backspace', 'A', 'b', '?')
}
```

## Text Message

No **Text Request** is expected from the server.

**Text Response** can be sent during interactive login.
It simulates a paste (Ctrl+V) event with a given text:

```typescript
{
    type: "text";   // Always "text"
    text: "...";    // The text to input
}
```
